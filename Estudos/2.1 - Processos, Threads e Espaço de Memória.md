# Processos, Threads e Espaço de Memória

### 1. Introdução: A Unidade de Execução no Sistema Operacional

Para entender como criar programas paralelos de alto desempenho, precisamos responder a uma pergunta essencial: **como o Sistema Operacional organiza e executa nosso código?**

Quando escrevemos um programa em C, C++ ou Python e o compilamos, ele vive no disco como um arquivo inerte (um binário). No momento em que mandamos executá-lo, o Sistema Operacional o carrega para a memória RAM e cria uma **unidade de execução**.

Essa unidade de execução pode assumir duas formas principais:
1. **Processo:** Uma entidade pesada, totalmente isolada e independente.
2. **Thread ("Processo Leve"):** Uma linha de execução que coexiste com outras dentro do mesmo processo, compartilhando recursos e memória.

Vamos explorar processos e threads para entender como a memória é organizada, por que a troca de contexto entre eles custa tempo e como isso impacta diretamente o desenvolvimento de software concorrente.

### 2. A Analogia da Filial vs. Trabalhadores na Mesma Sala

Para fixar a diferença conceitual antes de entrarmos nos detalhes técnicos de kernel:

```
+-----------------------------------------------------------------------+
|  ANALOGIA: A EMPRESA E SEUS FUNCIONÁRIOS                              |
|                                                                       |
|  PROCESSO = Uma Filial Independente da Empresa                        |
|  - Tem seu próprio prédio, escritórios e arquivo morto trancado.     |
|  - Um funcionário de outra filial NÃO consegue abrir a gaveta daqui.  |
|  - Se uma filial falir ou pegar fogo, as outras continuam operando.   |
|  - Comunicar-se com outra filial exige enviar cartas/e-mails (IPC).    |
|                                                                       |
|  THREAD = Trabalhadores Dividindo a Mesma Sala na Mesma Filial        |
|  - Todos compartilham a mesma mesa central, os arquivos e o estoque.  |
|  - A comunicação é imediata: basta falar ou escrever na mesa comum.   |
|  - Cada trabalhador tem apenas seu próprio bloco de anotações (Stack).|
|  - Se um trabalhador fizer uma besteira grave (ex: derrubar o prédio),|
|    a filial inteira cai (Segmentation Fault cancela todo o processo). |
+-----------------------------------------------------------------------+
```

### 3. Anatomia de um Processo em Memória

Quando o sistema operacional cria um **Processo**, ele concede a ele um **espaço de endereçamento virtual único e isolado**. O processo "acha" que é o único dono de toda a memória RAM do computador.

O espaço de memória de um processo é dividido em camadas bem definidas:

![Imagem12](./imagens/12.jfif)

*Layout Clássico do Espaço de Endereçamento Virtual de um Processo*

### 3.1 Componentes do Espaço de Memória:

1. **Segmento TEXT (Código):** Contém as instruções em linguagem de máquina executadas pela CPU. É marcado como **apenas leitura (*Read-Only*)** para evitar que o programa sobrescreva o próprio código por engano.
2. **Segmento DATA:** Guarda variáveis **globais e estáticas** que foram inicializadas com valor no código (ex: `int contador = 100;`).
3. **Segmento BSS (*Block Started by Symbol*):** Guarda variáveis globais e estáticas que **não** foram inicializadas explicitamente (são zeradas pelo SO na inicialização).
4. **HEAP (Monte):** Região de memória destinada à **alocação dinâmica em tempo de execução** (via `malloc()`, `calloc()` em C ou `new` em C++). Cresce em direção aos endereços mais altos.
5. **STACK (Pilha):** Guarda o contexto de execução de cada função chamada: variáveis locais, parâmetros passados e o endereço de retorno. Cresce em direção aos endereços mais baixos.

### 3.2 O Bloco de Controle do Processo (PCB - *Process Control Block*)
Além da memória, o Kernel do SO mantém uma estrutura de dados oculta para gerenciar o processo:
* **PID (*Process ID*):** Identificador único no sistema.
* **Tabela de Páginas (*Page Table*):** Mapeia os endereços virtuais do processo para os quadros de memória RAM física.
* **Tabela de Descritores de Arquivos:** Guarda os arquivos, *sockets* e *pipes* abertos pelo processo.
* **Estado e Registradores:** Salva o valor do acumulador, ponteiros de pilha e o *Program Counter* (PC) quando o processo é suspenso.

### 4. O Mecanismo Copy-On-Write (COW) no `fork()`

No Linux/Unix, um novo processo é criado duplicando um processo existente através da chamada de sistema `fork()`.

Se o processo pai tiver 4 GB de memória RAM alocada, copiar ingenuamente todos esses 4 GB para o processo filho a cada `fork()` tornaria o sistema terrivelmente lento.

Para resolver isso, os kernels modernos utilizam a técnica **Copy-On-Write (COW - Cópia na Escrita)**:

```
[PROCESSO PAI]                              [PROCESSO FILHO]
Page Table PAI                              Page Table FILHO
      |                                           |
      +--------------> [PÁGINAS FÍSICAS] <--------+
                        (Marcadas como READ-ONLY)
                                  |
            Quando o FILHO tenta ESCREVER em uma página:
                                  |
                                  v
                   [O SO Intercepta a Falha (Page Fault)]
                   [Copia APENAS aquela página de 4 KB]
                   [Aloca nova página privada para o Filho]
```

1. Quando o `fork()` executa, o SO **não copia a RAM**. Ele apenas duplica a *Tabela de Páginas*.
2. As páginas físicas são marcadas como **Read-Only** para ambos os processos.
3. Se Pai e Filho apenas lerem os dados, eles compartilham a mesma RAM física sem nenhum custo de cópia!
4. Apenas no momento em que um deles tenta **modificar (escrever)** um dado, o hardware gera uma exceção de *Page Fault*. O kernel intervém, **copia somente aquela página específica de 4 KB** e atualiza o mapeamento.

### 5. Anatomia de uma Thread ("Processo Leve")

Uma **Thread** é a menor unidade de código que o escalonador do SO consegue colocar para rodar em um núcleo de CPU.

Diferente de dois processos distintos, **todas as threads criadas dentro do mesmo processo compartilham exatamente o mesmo espaço de endereçamento virtual!**

![Imagem13](./imagens/13.jfif)

*Estrutura Interna de Múltiplas Threads Compartilhando um Processo*

### O que as Threads COMPARTILHAM:
* **Código (Segmento TEXT):** Todas executam as mesmas funções do programa.
* **Variáveis Globais e Estáticas (DATA e BSS):** Qualquer alteração feita pela Thread A em uma variável global fica imediatamente visível para a Thread B.
* **HEAP (Alocação Dinâmica):** Se a Thread A faz `malloc()` e passa o ponteiro para a Thread B, a Thread B acessa a memória diretamente.
* **Recursos do SO:** Descritores de arquivos abertos, sockets de rede, diretório corrente e permissões.

### O que cada Thread possui de PRIVADO:
* **Thread ID (TID):** Identificador exclusivo da thread.
* **Registradores da CPU:** Cada thread tem seus próprios valores armazenados de registradores (incluindo o *Program Counter* / PC).
* **STACK (Pilha Própria):** Cada thread recebe sua própria área de pilha reservada no espaço do processo para armazenar suas variáveis locais e histórico de chamadas de função.

### 6. Custo de Criação e Troca de Contexto (*Context Switch*)

O escalonador do Sistema Operacional alterna constantemente qual processo ou thread está rodando em qual núcleo da CPU. Essa transição se chama **Troca de Contexto (*Context Switch*)**.

### Troca de Contexto Entre Processos (Pesada):
1. Salva registradores da CPU do Processo A no PCB.
2. **Troca a Tabela de Páginas** no registrador da MMU (`CR3` no x86).
3. **Invalida o TLB (*Translation Lookaside Buffer*)**: A cache de tradução de endereços de memória da CPU é descartada.
4. As memórias cache L1/L2 do núcleo sofrem *Cache Misses* massivos porque os dados do novo processo não estão lá.
5. **Custo:** De centenas a milhares de ciclos de clock (vários microssegundos).

### Troca de Contexto Entre Threads do Mesmo Processo (Leve):
1. Salva registradores da CPU da Thread 1 (incluindo ponteiro de pilha e PC).
2. Carrega registradores da CPU da Thread 2.
3. **NÃO troca a Tabela de Páginas!**
4. **NÃO invalida o TLB!** As rotinas e caches de memória continuam válidas.
5. **Custo:** Poucos nanossegundos (ordens de grandeza mais rápido).

### 7. Exemplos Práticos em Código C

Vamos ver a diferença prática de comportamento de memória entre `fork()` (processos) e `pthread_create()` (threads).

### Exemplo A: Isolamento de Memória em Processos (`fork`)

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int valor_global = 100; // Variável compartilhada? Não após o fork!

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        printf("Erro ao criar processo!\n");
        return 1;
    } 
    else if (pid == 0) {
        // PROCESSO FILHO
        valor_global += 50; // Modifica a SUA cópia privada
        printf("[FILHO] valor_global modificado para: %d (Endereço: %p)\n", 
                valor_global, (void*)&valor_global);
    } 
    else {
        // PROCESSO PAI
        wait(NULL); // Aguarda o filho terminar
        printf("[PAI]   valor_global continua sendo:   %d (Endereço: %p)\n", 
                valor_global, (void*)&valor_global);
    }

    return 0;
}
```

**Saída no Terminal:**
```text
[FILHO] valor_global modificado para: 150 (Endereço: 0x55a1b2c04010)
[PAI]   valor_global continua sendo:   100 (Endereço: 0x55a1b2c04010)
```
> **Observação crucial:** Embora Pai e Filho mostrem o **mesmo endereço virtual**, as páginas físicas subjacentes foram separadas pelo mecanismo Copy-On-Write. A alteração do Filho NÃO afetou o Pai!

---

### Exemplo B: Compartilhamento de Memória em Threads (`pthreads`)

```c
#include <stdio.h>
#include <pthread.h>

int valor_global = 100; // Variável REALMENTE compartilhada entre threads

void* tarefa_thread(void* arg) {
    valor_global += 50; // Modifica a memória compartilhada
    printf("[THREAD] Modifiquei valor_global para: %d\n", valor_global);
    return NULL;
}

int main() {
    pthread_t thread_id;

    printf("[MAIN]   Valor inicial de valor_global: %d\n", valor_global);

    // Cria a thread
    pthread_create(&thread_id, NULL, tarefa_thread, NULL);

    // Aguarda a thread finalizar
    pthread_join(thread_id, NULL);

    printf("[MAIN]   Valor final de valor_global:   %d\n", valor_global);

    return 0;
}
```

**Saída no Terminal:**
```text
[MAIN]   Valor inicial de valor_global: 100
[THREAD] Modifiquei valor_global para: 150
[MAIN]   Valor final de valor_global:   150
```
> **Observação crucial:** A alteração feita dentro da thread foi refletida diretamente na função `main`, provando que ambas compartilham a mesma memória global.

### 8. Resumo

| Característica | **Processo** | **Thread** |
| :--- | :--- | :--- |
| **Isolamento de Memória** | **Total.** Espaço de endereçamento privado. | **Compartilhado.** Mesmo Heap, Data e Text. |
| **Recursos Privados** | Tabela de Páginas, Descritores de Arquivo, PCB, Stack. | Registradores, Program Counter (PC), Stack. |
| **Custo de Criação** | **Alto** (alocação de estruturas de kernel e tabelas). | **Baixo** (apenas alocação de Stack própria). |
| **Troca de Contexto** | **Lenta** (invalida TLB e exige troca de MMU). | **Rápida** (mantém TLB e MMU intactos). |
| **Comunicação (IPC)** | Complexa (Sockets, Pipes, Shmget, Arquivos). | Direta (Leitura e Escrita em variáveis globais/heap). |
| **Tolerância a Falhas** | **Alta.** Se um processo cai, outros continuam. | **Baixa.** Se uma thread gera *SegFault*, todo o processo cai. |
