# Estratégias de Decomposição — Decomposição de Dados, Funcional e Divisão e Conquista

Compreender as diferentes estratégias conceituais para fatiar um problema computacional em partes paralelas, comparando a **Decomposição de Dados**, a **Decomposição Funcional** e a **Decomposição por Divisão e Conquista**, entendendo quando aplicar cada uma para obter o máximo desempenho e balanceamento de carga.

---

### 1. O que é Decomposição e Por Que Ela é Crucial?

Antes de escrever qualquer linha de código em OpenMP, MPI ou CUDA, a primeira grande pergunta que o projetista de software paralelo deve fazer é: **"Como vou dividir esse problema entre meus núcleos de processamento?"**

A essa divisão estratégica dá-se o nome de **Decomposição**.

Se você tentar paralelizar um código sem uma estratégia clara de decomposição, cairá em um de dois extremos perigosos:
1. **Granularidade Fina Demais:** Múltiplas tarefas minúsculas onde o custo de criar e sincronizar threads é maior do que o tempo do próprio cálculo (overhead sufoca o ganho).
2. **Desbalanceamento Severo:** Uma thread fica encarregada de 90% do trabalho pesado enquanto as outras terminam rapidamente e ficam ociosas esperando na barreira de sincronização.

### 1.1 Analogia da Vida Real: A Grande Reforma da Casa

Pense em um projeto de reforma completa de uma casa de 4 cômodos:

* **Decomposição de Dados (Particionamento por Espaço):** Você contrata 4 pintores idênticos. Cada pintor fica responsável por pintar 1 cômodo específico da casa. Todos estão fazendo a mesma tarefa (pintar parede), mas cada um opera sobre uma "fatia de dados" diferente (um cômodo diferente).
* **Decomposição Funcional (Particionamento por Habilidade):** Você contrata 1 eletricista, 1 encanador, 1 pintor e 1 marceneiro. Cada profissional faz um trabalho completamente diferente e especializado na casa inteira.
* **Decomposição por Divisão e Conquista (Trabalho Recursivo):** O mestre de obras pega a lista de 100 tarefas da casa, divide em 2 listas de 50 para dois encarregados; cada encarregado divide em listas de 25 para seus subordinados, até que as tarefas fiquem simples o suficiente para serem executadas imediatamente por um operário.

### 2. Decomposição de Dados (Domain / Data Decomposition)

A **Decomposição de Dados** é a técnica mais comum e utilizada na computação de alto desempenho (HPC). Nela, a estrutura de dados principal do problema (um vetor, uma matriz, uma grade 3D, um conjunto de partículas ou um grafo) é fatiada entre os processadores. 

Cada processador ou thread executa o **mesmo conjunto de instruções**, mas aplicado exclusivamente ao seu pedaço atribuído do conjunto de dados.

*Diagrama exibindo uma matriz 2D sendo particionada de três formas: por linhas (1D 1D Block), por colunas (1D Column) e por blocos quadrados (2D Block-Block)*

![Imagem30](./imagens/30.jfif)

### 2.1 Padrões Comuns de Particionamento de Dados

Para vetores e matrizes, a forma como fatiamos os dados impacta diretamente a **localidade de memória nas caches** e o **balanceamento de carga**:

#### A) Particionamento por Bloco (Block Partitioning)
Dividem-se os $N$ elementos contíguos em $P$ blocos de tamanho aproximadamente $N/P$.
* **Exemplo:** Vetor com 1000 elementos e 4 threads:
  * Thread 0: índices `[0 .. 249]`
  * Thread 1: índices `[250 .. 499]`
  * Thread 2: índices `[500 .. 749]`
  * Thread 3: índices `[750 .. 999]`
* **Vantagens:** Excelente localidade espacial na cache L1/L2 (acesso contíguo em RAM / *Unit Stride*).
* **Desvantagens:** Se o trabalho por elemento variar (ex: cálculo de fractais de Mandelbrot, onde certas regiões da imagem exigem 1000 iterações e outras apenas 10), as threads do meio podem demorar muito mais que as outras, gerando **desbalanceamento de carga**.

#### B) Particionamento Cíclico (Cyclic / Round-Robin Partitioning)
Os elementos são distribuídos um a um de forma intercalada entre as threads.
* **Exemplo com 4 threads:**
  * Thread 0: elementos `0, 4, 8, 12, 16...`
  * Thread 1: elementos `1, 5, 9, 13, 17...`
  * Thread 2: elementos `2, 6, 10, 14, 18...`
  * Thread 3: elementos `3, 7, 11, 15, 19...`
* **Vantagens:** Excelente para balancear a carga em problemas onde o custo computacional varia gradualmente ao longo do vetor.
* **Desvantagens:** Péssima localidade de cache e alto risco de **False Sharing** (múltiplas threads alterando variáveis vizinhas na mesma linha de cache de 64 bytes).

#### C) Particionamento Bloco-Cíclico (Block-Cyclic Partitioning)
Divide-se o vetor em pequenos blocos de tamanho $K$ (ex: $K=16$ ou $K=64$) e distribui-se esses blocos de forma intercalada.
* **Vantagens:** Equilibra a localidade espacial (por processar blocos contíguos) com o balanceamento de carga (por distribuir os blocos pelo vetor inteiro). É o padrão adotado por bibliotecas numéricas de alto desempenho como o **ScaLAPACK**.

#### D) Particionamento Multidimensional (Grades 2D / 3D)
Em simulações físicas (como dinâmica dos fluidos, previsão do tempo e processamento de imagem), em vez de fatiar uma matriz apenas por linhas, fatiamos a matriz em **blocos retangulares/quadrados 2D**.
* **Por que fazer isso?** Reduz drasticamente o **perímetro de comunicação** em relação à área de computação. Se um subdomínio quadrado tem área $A 	imes A$, o volume de cálculo é $O(A^2)$, enquanto a fronteira que precisa ser trocada com os vizinhos (*Halo Exchange*) é de apenas $O(4A)$.

### 3. Decomposição Funcional (Functional / Task Decomposition)

Na **Decomposição Funcional**, em vez de fatiar os *dados*, fatiamos o *código*. Identificam-se tarefas que realizam computações totalmente distintas e que podem ser executadas simultaneamente.

*Diagrama do modelo Pipeline e do modelo Mestre-Trabalhador. No Pipeline, dados fluem do Estágio 1 -> Estágio 2 -> Estágio 3. No Mestre-Trabalhador, o Mestre distribui tarefas de uma fila para múltiplos trabalhadores*

### 3.1 Padrões Clássicos de Decomposição Funcional

#### Padrão Esteira / Pipeline
Análogo a uma linha de montagem de automóveis. O processamento de um dado é dividido em etapas sequenciais organizadas em estágios. Cada estágio é executado por uma thread dedicada.

* **Exemplo (Processamento de Vídeo em Tempo Real):**
  * **Thread 1 (Estágio A):** Lê quadros do arquivo de vídeo no disco.
  * **Thread 2 (Estágio B):** Aplica filtro de desfoque e ajuste de cor no quadro.
  * **Thread 3 (Estágio C):** Compacta o quadro via codec H.264.
  * **Thread 4 (Estágio D):** Grava o quadro compactado na rede.
* **Gargalo:** O desempenho do pipeline é limitado pelo **estágio mais lento** (o gargalo da esteira).

#### Padrão Mestre-Trabalhador (Master / Worker)
Uma thread "Mestre" mantém uma fila dinâmica de tarefas pendentes e gerencia o estado global. Várias threads "Trabalhadoras" pegam uma tarefa da fila, executam-na e devolvem o resultado ao Mestre.
* **Vantagens:** Excelente para balanceamento dinâmico em problemas heterogêneos. Se uma tarefa for muito pesada, uma thread trabalhadora levará mais tempo nela, enquanto outras threads pegam 2 ou 3 tarefas mais leves na fila.
* **Desvantagens:** Se o número de trabalhadores for muito alto (ex: centenas de threads), a fila central mantida pelo Mestre vira um **ponto único de contenção**.

### 4. Decomposição por Divisão e Conquista (Divide and Conquer)

A **Decomposição por Divisão e Conquista** combina elementos de dados e tarefas de maneira recursiva. É a estratégia ideal para algoritmos recursivos estruturados em árvore.

### 4.1 Como Funciona a Abordagem Paralela:
1. **Divisão (Divide):** Se o problema for maior do que um tamanho limite de corte (*threshold*), divida-o em 2 ou mais subproblemas independentes.
2. **Conquista (Conquer):** Crie tarefas paralelas para resolver cada subproblema de forma assíncrona.
3. **Combinação (Combine):** Aguarde a conclusão das tarefas filhas e combine seus resultados para formar a resposta do problema pai.

*Árvore recursiva de execução do Quicksort/Mergesort. O nó raiz (Problema N) gera dois nós filhos (N/2), que geram quatro nós netos (N/4), executando em paralelo*

![Imagem32](./imagens/32.jfif)

### 4.2 O Conceito de Corte (*Cutoff Threshold*)
Um erro clássico em Divisão e Conquista paralela é continuar gerando tarefas paralelas recursivamente até vetores de tamanho 1 ou 2.
* **A Regra de Ouro:** Quando o tamanho do subproblema fica menor que um certo limite (ex: $N < 1000$ elementos), interrompe-se a criação de novas threads/tarefas e resolve-se o subproblema de forma **sequencial direta**. Isso elimina o overhead de gerenciamento do ambiente paralelo.

### 5. Exemplos Práticos de Código em C (OpenMP)

Vamos analisar dois programas completos demonstrando a **Decomposição de Dados** e a **Decomposição por Divisão e Conquista**.

### Exemplo 1: Decomposição de Dados (Soma de Vetor em Bloco vs. Cíclico)

```c
#include <stdio.h>
#include <stdlib.h>
#include <omp.h>

#define N 10000000

int main() {
    double *A = (double*) malloc(N * sizeof(double));
    double *B = (double*) malloc(N * sizeof(double));
    double *C = (double*) malloc(N * sizeof(double));

    // Inicialização dos dados
    for (int i = 0; i < N; i++) {
        A[i] = 1.0;
        B[i] = 2.0;
    }

    double inicio = omp_get_wtime();

    // DECOMPOSIÇÃO DE DADOS POR BLOCO (Estática e Contígua)
    // O OpenMP divide N em blocos contínuos de tamanho N / num_threads
    #pragma omp parallel for schedule(static)
    for (int i = 0; i < N; i++) {
        C[i] = A[i] + B[i];
    }

    double fim = omp_get_wtime();
    printf("[Decomposição por Bloco] Tempo: %.5f segundos
", fim - inicio);

    // DECOMPOSIÇÃO DE DADOS CÍCLICA (Tamanho de bloco = 1)
    inicio = omp_get_wtime();
    #pragma omp parallel for schedule(static, 1)
    for (int i = 0; i < N; i++) {
        C[i] = A[i] + B[i];
    }
    fim = omp_get_wtime();
    printf("[Decomposição Cíclica]   Tempo: %.5f segundos
", fim - inicio);

    free(A); free(B); free(C);
    return 0;
}
```

### Exemplo 2: Decomposição por Divisão e Conquista (Mergesort com Tasks no OpenMP)

```c
#include <stdio.h>
#include <stdlib.h>
#include <omp.h>

#define THRESHOLD 1000 // Limite de corte para alternar para execução sequencial

void merge(int *arr, int l, int m, int r) {
    int n1 = m - l + 1;
    int n2 = r - m;
    int *L = (int*) malloc(n1 * sizeof(int));
    int *R = (int*) malloc(n2 * sizeof(int));

    for (int i = 0; i < n1; i++) L[i] = arr[l + i];
    for (int j = 0; j < n2; j++) R[j] = arr[m + 1 + j];

    int i = 0, j = 0, k = l;
    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) arr[k++] = L[i++];
        else arr[k++] = R[j++];
    }
    while (i < n1) arr[k++] = L[i++];
    while (j < n2) arr[k++] = R[j++];

    free(L); free(R);
}

void mergesort_sequencial(int *arr, int l, int r) {
    if (l < r) {
        int m = l + (r - l) / 2;
        mergesort_sequencial(arr, l, m);
        mergesort_sequencial(arr, m + 1, r);
        merge(arr, l, m, r);
    }
}

void mergesort_paralelo(int *arr, int l, int r) {
    if (l < r) {
        // CORTE (THRESHOLD): Se o vetor for pequeno, executa sequencialmente
        if (r - l < THRESHOLD) {
            mergesort_sequencial(arr, l, r);
            return;
        }

        int m = l + (r - l) / 2;

        // DIVISÃO E CONQUISTA COM TAREFAS PARALELAS
        #pragma omp task shared(arr) firstprivate(l, m)
        mergesort_paralelo(arr, l, m);

        #pragma omp task shared(arr) firstprivate(m, r)
        mergesort_paralelo(arr, m + 1, r);

        // COMBINAÇÃO: Aguarda as duas tarefas filhas terminarem antes do merge
        #pragma omp taskwait
        merge(arr, l, m, r);
    }
}

int main() {
    int size = 100000;
    int *arr = (int*) malloc(size * sizeof(int));

    for (int i = 0; i < size; i++) arr[i] = rand() % 10000;

    double t_inicio = omp_get_wtime();

    #pragma omp parallel
    {
        #pragma omp single
        {
            // Apenas uma thread inicia a raiz da árvore de Divisão e Conquista
            mergesort_paralelo(arr, 0, size - 1);
        }
    }

    double t_fim = omp_get_wtime();
    printf("Mergesort Paralelo concluído em: %.5f segundos
", t_fim - t_inicio);

    free(arr);
    return 0;
}
```

### 6. Tabela Comparativa das Estratégias de Decomposição

| Característica | Decomposição de Dados | Decomposição Funcional | Divisão e Conquista |
| :--- | :--- | :--- | :--- |
| **Foco da Divisão** | Estruturas de dados (vetores, matrizes, grades). | Funções/etapas do algoritmo. | Subproblemas recursivos independentes. |
| **Homogeneidade** | **Alta:** Todas as threads executam o mesmo código. | **Baixa:** Cada thread executa uma função diferente. | **Média/Alta:** Estrutura parecida em níveis da árvore. |
| **Balanceamento de Carga** | Estático ou Bloco-Cíclico; simples de prever. | Depende do tempo de execução de cada estágio/função. | Dinâmico (via roubo de tarefas / *work stealing*). |
| **Padrões Típicos** | SPMD (*Single Program, Multiple Data*). | Pipeline, Mestre-Trabalhador, Cliente-Servidor. | Árvore de Tarefas (*Task Parallelism*). |
| **Ideal Para** | Processamento de imagens, multiplicação de matrizes, simulações de física. | Compiladores, encoders de áudio/vídeo, web servers. | Quicksort, Mergesort, Árvores de Pesquisa, Algoritmos em Grafos. |
