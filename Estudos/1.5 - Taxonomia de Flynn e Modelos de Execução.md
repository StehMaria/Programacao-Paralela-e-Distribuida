# Taxonomia de Flynn e Modelos de Execução (SISD, SIMD, MISD, MIMD, SPMD e MPMD)

### 1. Introdução: Como Classificar a Diversidade do Paralelismo?

Imagine que você foi contratado para gerenciar uma cozinha de restaurante extremamente movimentada. Dependendo de como você organiza a equipe de cozinheiros (os **processadores**) e as receitas/pedidos que eles recebem (as **instruções** e **dados**), a dinâmica de trabalho muda completamente:

1. Um único cozinheiro preparando um prato por vez.
2. Um chefe gritando **uma única ordem** ("Corte 10 tomates!") para 10 ajudantes cortarem seus respectivos tomates em paralelo.
3. Múltiplos cozinheiros preparando pratos completamente diferentes simultaneamente.

Em 1966, **Michael J. Flynn** propôs um sistema de classificação simples, elegante e universal para organizar todas as arquiteturas de computadores conhecidas. Essa classificação é baseada no número de **Fluxos de Instruções** (*Instruction Streams*) e **Fluxos de Dados** (*Data Streams*) que o sistema consegue processar simultaneamente.

### 2. As Quatro Categoria de Flynn em Detalhes

### 2.1. SISD (Single Instruction, Single Data) — O Computador Tradicional

* **Conceito:** Uma única Unidade de Controle lê **uma instrução por vez** da memória, e essa instrução atua sobre **um único elemento de dado**.
* **Analogia:** Um único cozinheiro preparando uma única receita do início ao fim.
* **Hardware:** Os computadores sequenciais clássicos de núcleo único (ex: Intel Pentium I/II, microcontroladores simples como Arduino UNO).
* **Fluxo de Execução:**
  ```
  [Instrução: Soma] ---> [Dado A, Dado B] ---> [Resultado C]
  ```

---

### 2.2. SIMD (Single Instruction, Multiple Data) — O Processamento Vetorial

* **Conceito:** Uma única Unidade de Controle despacha **uma única instrução**, mas essa instrução é executada **simultaneamente sobre múltiplos dados** armazenados em registradores vetoriais.
* **Analogia:** O chefe de cozinha grita "Tempere com sal!", e 8 ajudantes jogam sal em 8 bifes diferentes ao mesmo tempo, exatamente no mesmo instante.
* **Hardware:** 
  * Extensões vetoriais de CPUs modernas: **Intel SSE, AVX, AVX-512**, **ARM NEON**.
  * Unidades de processamento gráfico (**GPUs**).
* **Funcionamento Interno:**

```
          +-----------------------+
          |  Unidade de Controle  |
          +-----------+-----------+
                      | (Instrução Única: VADD)
         +------------+------------+
         |            |            |
         v            v            v
      [ ULA 0 ]    [ ULA 1 ]    [ ULA 2 ]   ...  [ ULA N ]
         |            |            |                  |
      A[0]+B[0]    A[1]+B[1]    A[2]+B[2]          A[N]+B[N]
```

#### Exemplo de Código em C (Escalar vs Vetorial SIMD com AVX2)

##### Versão Escalar (Processamento Elemento por Elemento):
```c
void soma_vetores_escalar(float *a, float *b, float *c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i]; // Processa 1 float (32 bits) por iteração
    }
}
```

##### Versão SIMD com Intrínsicas AVX2 (Processa 8 floats simultaneamente em registrador de 256 bits):
```c
#include <immintrin.h> // Header para intrínsecas AVX/AVX2

void soma_vetores_avx2(float *a, float *b, float *c, int n) {
    // Processa blocos de 8 elementos por iteração (256 bits / 32 bits = 8 floats)
    for (int i = 0; i < n; i += 8) {
        __m256 va = _mm256_loadu_ps(&a[i]); // Carrega 8 floats de 'a'
        __m256 vb = _mm256_loadu_ps(&b[i]); // Carrega 8 floats de 'b'
        __m256 vc = _mm256_add_ps(va, vb);   // Soma os 8 pares de uma vez!
        _mm256_storeu_ps(&c[i], vc);        // Salva os 8 resultados em 'c'
    }
}
```

### 2.3. MISD (Multiple Instruction, Single Data) — O Paralelismo de Redundância

* **Conceito:** Múltiplas instruções operam simultaneamente sobre **o mesmo fluxo de dados**.
* **Analogia:** Vários médicos examinando a **mesma radiografia** de um paciente, aplicando diferentes diagnósticos de forma independente para comparar conclusões.
* **Hardware:** Extremamente raro em sistemas genéricos. É utilizado em **sistemas críticos e tolerantes a falhas** onde a segurança é vital (ex: sistemas de navegação aeroespacial como o Ônibus Espacial da NASA ou controle de reatores nucleares).
* **Mecanismo:** Os mesmos dados de sensores passam por 3 ou 4 processadores com softwares e algoritmos diferentes. Se um software falhar ou dar resultado divergente, o sistema escolhe o resultado pela maioria (*votador*).

---

### 2.4. MIMD (Multiple Instruction, Multiple Data) — O Padrão da Computação de Alto Desempenho

* **Conceito:** Múltiplos processadores autônomos executam **instruções diferentes sobre dados diferentes** de forma totalmente independente.
* **Analogia:** Uma brigada de cozinha completa onde um cozinheiro assa carne, outro prepara a sobremesa e outro monta saladas. Cada um tem sua receita e seus ingredientes.
* **Hardware:**
  * Processadores *multicore* / *multisocket* modernos (Intel Xeon, AMD EPYC, Apple M-Series).
  * Clusters de computadores e supercomputadores.

---

## 3. Estruturação do Código em Sistemas MIMD: SPMD vs MPMD

Dentro da categoria **MIMD**, como os programadores organizam o software? Existem dois grandes modelos de execução de software: **SPMD** e **MPMD**.

```
                           SISTEMAS MIMD
                                 |
            +--------------------+--------------------+
            |                                         |
     Modelo SPMD                               Modelo MPMD
(Single Program, Multiple Data)           (Multiple Program, Multiple Data)
  - Um único arquivo executável             - Múltiplos arquivos executáveis
  - Ramos lógicos por ID (rank)             - Códigos totalmente especializados
  - Padrão em OpenMP e MPI                  - Mestre/Escravo, Módulos heterogêneos
```

---

### 3.1. SPMD (Single Program, Multiple Data)

* **O que é:** Existe **apenas um arquivo executável** compilado. Todos os nós ou threads iniciam o mesmo programa, mas cada worker descobre seu identificador único (*Rank* no MPI ou *Thread ID* no OpenMP) e toma decisões lógicas ou processa partições de dados diferentes.
* **Vantagem:** Muito fácil de gerenciar, compilar e implantar em centenas de nós. É o modelo dominante em HPC.

#### Exemplo Prático de Código SPMD (Pseudo-C com MPI/OpenMP)

```c
#include <stdio.h>

int main() {
    int id = get_process_id(); // Obtém o ID único do processo (ex: 0, 1, 2, 3)
    int total_processos = get_total_processes();

    // Mesmo código rodando em todos os nós, mas ramificando pelo ID!
    if (id == 0) {
        printf("[Processo Mestre %d] Coletando resultados e gerando relatório...
", id);
    } else {
        printf("[Processo Trabalhador %d] Calculando fatia %d do problema...
", id, id);
        // Executa cálculo na fatia de dados local
    }

    return 0;
}
```

---

### 3.2. MPMD (Multiple Program, Multiple Data)

* **O que é:** São compilados e executados **dois ou mais programas executáveis totalmente diferentes** que rodam em paralelo e trocam dados entre si.
* **Onde é usado:**
  * **Modelo Mestre-Escravo Estrutural:** Um programa `mestre.exe` encarregado apenas de gerenciamento da fila de tarefas e outro programa `trabalhador.exe` dedicado puramente a efetuar cálculos.
  * **Simulações Multifísicas Acopladas:** Por exemplo, o executável `aerodinamica.exe` simula o fluxo de ar em torno de um avião e envia a distribuição de pressão via rede para o executável `estrutural.exe`, que calcula a deformação das asas.

## 4. Visão Consolidada

Vamos conectar todas as partes do hardware ao software:

1. **Von Neumann & Gargalos:** Vimos que a busca de dados na RAM pelo barramento cria o *Memory Wall*.
2. **Caches:** Aprendemos como as caches L1, L2 e L3 tentam esconder essa latência usando localidade espacial e temporal, e como o *False Sharing* pode destruir esse benefício.
3. **UMA vs NUMA:** Descobrimos que, ao colocar múltiplos soquetes, a memória passa a ter acessos Não-Uniformes, exigindo a política de *First-Touch*.
4. **Clusters:** Quando um único servidor não basta, conectamos vários servidores via rede (*scale-out*), migrando da memória compartilhada para a memória distribuída.
5. **Flynn, SIMD/MIMD, SPMD/MPMD:** Agrupamos todas essas máquinas na Taxonomia de Flynn. As CPUs e GPUs usam **SIMD** internamente para acelerar vetores, interconectam núcleos em **MIMD**, e nós programamos em **SPMD** (com OpenMP/MPI) para fazer a máquina produzir resultado eficiente.
